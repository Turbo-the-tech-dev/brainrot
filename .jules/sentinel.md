## 2026-03-10 - Command Injection in speak.sh
**Vulnerability:** The `speak.sh` script was extracting text from `GEMINI_BRAINROT.md` and passing it to `termux-tts-speak` without validation. Although the variables were double-quoted, malicious content could still cause issues if the underlying command had vulnerabilities or if the quoting was ever removed. Specifically, it was a fragile pattern for data derived from an external file.
**Learning:** Command substitution `$()` and backticks are still literals inside double quotes in shell assignments, but they are evaluated if they are part of a command line that gets expanded. However, my tests showed that `VAR='$(whoami)'` followed by `echo "$VAR"` does NOT execute `whoami`. The real risk in `speak.sh` was more about defense-in-depth and preventing the script from being used to "speak" control characters or shell metacharacters that might interact with the TTS engine or terminal in unexpected ways.
**Prevention:** Implement a proactive validation gate using regex to reject any input containing shell metacharacters (`\`, `` ` ``, `$`, `;`, `&`, `|`, `"`). Use `set -euo pipefail` for all shell scripts to ensure they fail fast on errors or unset variables.
